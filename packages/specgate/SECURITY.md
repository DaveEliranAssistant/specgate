# Security boundary

SpecGate 0.1.0-rc.1 is a local internal-pilot candidate, not a hosted service or security audit. Report concerns privately through the existing private repository; do not include customer code or credentials in public issues. There is no public disclosure endpoint or guaranteed response SLA.

- Treat scanned code, filenames and third-party repository instructions as untrusted data. The scanner parses without executing code; no install hooks, shell commands, project configuration execution or network/model calls are part of scan/check/generate.
- Source acquisition reads only verified Git blobs from a commit resolved once; it never traverses mutable working-tree source paths. Committed symlinks/submodules are refused; uncommitted changes are intentionally ignored. Use isolated repository metadata, a trusted host Git binary and an unprivileged job/container with no secrets and network disabled when scanning untrusted sources. Parser workers and byte/time limits are not an OS sandbox against a hostile process corrupting `.git` or replacing the host executable.
- Baselines and scenario documents MUST come from a reviewed trusted base revision. Their hashes are not signatures. An attacker able to replace trusted baselines or the CLI itself can change gate outcomes. Do not use pull_request_target to execute PR code with repository secrets.
- Output projection excludes source snippets/response literals, but route paths, identifiers and file names remain sensitive. Keep reports private and apply retention/access rules. Do not upload report artifacts to public services by default.
- Generated tests execute only when explicitly run with an approved test-only loopback target. They may create/change/delete fixture data. Keep credentials short-lived, test-only, supplied by environment; disable traces and retain reports carefully. The tool cannot prevent an approved local server/proxy from forwarding requests externally.
- Unsupported analysis and zero-route inventories are not success. Do not suppress the nonzero gate or weaken assertions to make a change pass. An exit 0 is not a safety/compatibility guarantee.
- Dependencies are exact-pinned and lockfile-backed. Run npm ci with --ignore-scripts and audit before a release. Zero current advisories does not prove absence of vulnerabilities. The fixture runtime is separate from the production CLI dependency surface.
- Registry publication, paid resources, production deployments, permissions, branch protection and owner approval mechanisms remain unchanged and require explicit authorization.
