# Additional developer-pilot boundary

The original package security model continues to apply, unchanged. The new report/collector imports the existing scanner/compiler, never service modules, and never installs target dependencies, starts target services, executes generated tests, contacts target URLs or calls a model. Git/object acquisition and parser limits are not an OS sandbox. Use isolated repository metadata and a trusted Git/Node runtime; scan without credentials and deny network at the container/job layer where required. The normal GitHub hosted job is not a demonstrated OS/network sandbox.

Trusted baseline/scenario documents must come from independently reviewed base revisions, never the proposed source branch. Checksums detect drift, not approval or authenticity. Review reference, classifications and scenario IDs are caller assertions, not identity/freshness proofs. Scenario values are validated by the existing compiler; only reference/ID/classification, method/path, expected status and body assertion kind are projected into the new report. Body/request assertion literals are not printed. Source registration/file identifiers, review references and expected status may still be confidential; retain reports privately.

The pilot CLI uses bounded no-follow JSON reads and exclusive new output files. Collector evidence must be a fresh directory outside the target, checked through real parent paths; it refuses reuse and symlink aliases into the target. These checks assume a trusted filesystem and do not defend a hostile concurrent ancestor substitution. Existing files are never deleted to clear a run. Use a fresh per-run workspace so a tool failure cannot be mistaken for an old report.

Observe-only collects native exits 0 and 1 while preserving their verdict/code in native and operational records. Exit 2, malformed input, unavailable tooling, timeouts and invalid reports remain collector errors. No `|| true` or default-green report. Do not use collector success as a production gate; no branch-protection/enforcement changes are made.

Keep the private scanner archive, cache, installed runtime and reports out of public repositories/artifacts. The private product CI retains synthetic proof/archive artifacts for 14 days; verify access before adoption. No PAT, broader operator credential or elevated fork trigger is a substitute for a narrowly scoped reader. Cross-repository authenticated distribution remains unqualified until a suitable private artifact and reader are approved and exercised.
